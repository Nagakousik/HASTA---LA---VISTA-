# Hasta La Vista — AI Interview Assistant

A voice-first mock interview app for campus placements. Add your resume, choose a company and role, and practise a timed interview with a browser-based AI recruiter that listens, responds, and saves the transcript.

Built with React, Vite, Firebase, and the browser's speech APIs. Groq can optionally drive the conversation; if it is unavailable, a scripted interview engine keeps the session running.

## What it does

1. **Sign in** with email/password or Google. Profiles, resumes, and interview sessions are stored in Firebase.
2. **Prepare** by pasting a resume or uploading a PDF, DOCX, TXT, or Markdown file. The resume is read locally in the browser.
3. **Pick a session**: company, role, and a 5-minute or 10-minute duration.
4. **Check your setup**: camera preview, microphone level, speaker playback, and authorized-name validation.
5. **Interview** in a video-call-style room with a recruiter persona, text-to-speech questions, speech-recognition answers, a countdown timer, live captions, and a transcript.
6. **Review** the finished transcript, answer count, question count, and why the interview ended.

The interview is voice-to-voice. Typed answers are available as a fallback when speech recognition is unavailable.

## How the conversation engine works

- **Groq (primary):** When a Groq key and the `/api/groq` proxy are available, each middle turn is generated by a Groq-hosted model using the resume, recent conversation, interview phase, and time remaining.
- **Scripted engine (fallback):** `src/services/interviewEngine.js` builds complete interviews from the resume, role, company, and phase. It needs no network and is always available.
- **Safety rules:** A generated line is used only if it arrives within 4.5 seconds, is short and clean, is not a repeat, and is a question. Closing language and `conclude` flags from the model are rejected: only the application deadline can end the interview. Missing keys, invalid keys, HTTP 429s, network failures, and retired models all fall back to the scripted engine.
- **No early finish:** question counts, scripted pool exhaustion, and model-generated closing language cannot complete the session. The scripted engine keeps asking substantive questions while time remains.

Default model: `qwen/qwen3.8-27b`. Automatic fallback model: `llama-3.1-8b-instant`.

## Turn-taking and interview timing

The interview uses one authoritative deadline, created from the real start timestamp when the room opens.

- The countdown is always `deadline - Date.now()`. It is not accumulated from interval ticks, paused for speech synthesis, or rebased after a camera reconnect.
- Candidate answers are accumulated across recognition events, including interim results. The turn ends only after an adaptive silence: 5 seconds for a short answer, growing to 8 seconds for a long explanation. An open interim phrase adds a short grace period.
- Natural pauses, breathing, thinking, and pauses between sentences do not submit the answer. A completed answer is submitted exactly once.
- The AI cannot generate or speak another question while the candidate is talking. Text-to-speech finishes before listening begins.
- Non-response handling is unchanged: a 20-second wait, then two 20-second follow-ups, then a single conclusion.
- When the deadline expires, the active turn is allowed to finish. No new normal question starts. One closing statement is spoken, the transcript is saved once, and the app navigates to the results page.
- A safety limit of two minutes of continuous speech endpoints a candidate who never pauses, so the room cannot hang forever.

## Getting started

### Requirements

- Node.js 20.19+ or 22.12+ (Vite 8 requirement; tested with Node 24)
- npm
- Chrome or Edge is recommended for speech recognition and speech synthesis
- A Firebase project
- Optional: a free Groq API key

### Install

```sh
npm install
```

### Configure environment variables

Copy the example file and fill in your values:

```sh
cp .env.example .env.local
```

On Windows PowerShell:

```powershell
Copy-Item .env.example .env.local
```

`.env.local` is ignored by Git. Never commit real keys.

#### Firebase variables

Set all six values from **Firebase Console → Project settings → Your apps → Web app**:

```dotenv
VITE_FIREBASE_API_KEY=
VITE_FIREBASE_AUTH_DOMAIN=
VITE_FIREBASE_PROJECT_ID=
VITE_FIREBASE_STORAGE_BUCKET=
VITE_FIREBASE_MESSAGING_SENDER_ID=
VITE_FIREBASE_APP_ID=
```

These values identify the Firebase project and are safe to ship in a browser bundle. Firestore security rules, not the web API key, protect user data.

#### Groq variables (optional)

```dotenv
# Server-side only. Used by the Vite dev/preview proxy at /api/groq.
GROQ_API_KEY=

# Optional. Defaults to qwen/qwen3.8-27b.
VITE_GROQ_MODEL=
```

`GROQ_API_KEY` must not use a `VITE_` prefix. Vite only exposes `VITE_*` variables to browser code.

### Firebase setup

1. Create a Firebase project and a Web app.
2. Enable **Email/Password** and **Google** under **Authentication → Sign-in method**.
3. Add your local and deployed domains under **Authentication → Settings → Authorized domains**.
4. Create a Firestore database.
5. Publish the rules in `firestore.rules`:
   - Firebase Console → **Firestore Database → Rules**, or
   - `firebase deploy --only firestore:rules` with the included `firebase.json`.

The rules restrict every user to their own profile and interviews:

```text
users/{uid}
users/{uid}/interviews/{interviewId}
```

Until the rules are published, sign-in can still succeed, but saving a resume or starting an interview will fail because Firestore rejects the writes. The app surfaces these failures instead of crashing.

### Groq setup (optional)

1. Create a key at <https://console.groq.com/keys>.
2. Add it to `.env.local` as `GROQ_API_KEY`.
3. Restart the dev server.
4. Verify it:

```sh
npm run check:ai
```

This makes one small request and prints the HTTP status and remaining free-tier requests. If no key is configured, it reports that the scripted interview will be used.

### Run locally

```sh
npm run dev
```

Open the URL printed by Vite, usually <http://localhost:5173>.

## Available scripts

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the Vite development server with the `/api/groq` proxy |
| `npm run build` | Create a production build in `dist/` |
| `npm run preview` | Serve the production build locally with the `/api/groq` proxy |
| `npm run lint` | Run Oxlint |
| `npm run test` | Run the deterministic turn-taking and deadline regression tests |
| `npm run check:ai` | Test the configured Groq key and model with one small request |

The automated tests use Node's built-in test runner and fake timestamps. They cover adaptive silence, interim results, recognition restarts, duplicate submissions, stale callbacks, the authoritative deadline, graceful expiry, exactly-once completion, and the scripted engine's refusal to conclude early. They do not exercise a real microphone or browser speech recognition; those still require a manual walkthrough of the sign-in → preparation → device check → interview → results flow.

## Privacy and security

- Firebase web configuration is public by design. Firestore rules enforce per-user access.
- `GROQ_API_KEY` is read only by the Vite dev/preview proxy. It is never included in the built bundle.
- Resumes are parsed locally in the browser before the extracted text is saved to Firestore.
- The Groq key is never stored in Firestore.
- The app uses camera and microphone permissions only during the device check and interview. Media streams are released when you leave the room.

## Development vs production

The `/api/groq` proxy in `vite.config.js` exists only for `npm run dev` and `npm run preview`. It adds the `Authorization` header server-side, so the browser never sees `GROQ_API_KEY`.

A static deployment of `dist/` has no proxy. The app detects the failed Groq request and continues with the scripted engine. For production AI conversation, deploy a server-side or serverless endpoint at `/api/groq` (or change `ENDPOINT` in `src/services/groqBrain.js`) that forwards requests to `https://api.groq.com/openai/v1/chat/completions` with the key attached.

## Browser support and limitations

- **Chrome and Edge** are the primary targets. Speech recognition via `SpeechRecognition` / `webkitSpeechRecognition` is not available in every browser; Firefox support is limited.
- Browser speech recognition may use the browser vendor's servers. Typed answers work without it.
- The recruiter avatar is an initials avatar, not a live video or animated face.
- The results page lists the transcript and session metadata. It does not calculate a score, readiness rating, or hiring recommendation.
- The app is a practice tool. Name validation is a client-side heuristic and does not verify identity against official records.
- Camera access is required to enter the interview. If the camera is lost mid-session, the room pauses and offers reconnection. The interview clock keeps running because the selected duration is authoritative.
- The production bundle currently emits a Vite warning about chunks larger than 500 kB. This is expected from the Firebase and PDF/DOCX dependencies and does not prevent the build.
- `npm audit` reports four high-severity advisories in the transitive `@grpc/grpc-js` dependency of Firebase. The suggested fix downgrades Firebase to 9.x, which is a breaking change. The app stays on Firebase 13.x; review this before exposing the app to untrusted users.
